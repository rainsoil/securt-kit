# Securt-Kit 混合配置使用说明

## 概述

Securt-Kit 支持两种字段加密配置方式：
1. **注解配置**：在实体类字段上使用 `@FieldEncryptor` 注解
2. **配置文件配置**：在 `application.yml` 中集中配置字段加密策略

两种方式可以混合使用，配置文件中的配置会覆盖注解配置。

## 配置方式对比

### 注解配置（声明式）
```java
@TableName("test_user")
public class User {
    @FieldEncryptor(Md5PoJoFieldEncryptorStrategy.class)
    @TableField("password")
    private String password;  // MD5加密
    
    @FieldEncryptor(DefaultPoJoFieldEncryptorPattern.class)
    @TableField("phone")
    private String phone;     // DES加密
}
```

**优点：**
- 字段和加密策略紧耦合，易于理解
- 代码自文档化
- 编译时检查

**缺点：**
- 修改加密策略需要重新编译
- 无法动态调整
- 配置分散在各个实体类中

### 配置文件配置（集中式）
```yaml
securt-kit:
  field-encryptor:
    enabled: true
    # 默认加密策略（当字段未配置时使用）
    default-strategy: com.chu7.securtkit.encryptor.pojo.DefaultPoJoFieldEncryptorPattern
    
    # 表字段加密配置
    tables:
      test_user:
        enabled: true
        fields:
          password:
            strategy: com.chu7.securtkit.encryptor.pojo.AesPoJoFieldEncryptorStrategy
            params:
              key: "custom-aes-key"
          phone:
            # 不配置strategy，将使用default-strategy
          # age字段不配置，表示不加密
```

**优点：**
- 集中管理，易于维护
- 支持动态配置
- 支持参数化配置
- 可以覆盖注解配置

**缺点：**
- 配置和代码分离
- 运行时才能发现配置错误
- 配置相对复杂

## 混合配置策略

### 1. 优先级规则
配置文件 > 注解配置

### 2. 使用场景

#### 场景1：注解为主，配置文件补充
```java
// 实体类中使用注解定义默认加密策略
@TableName("test_user")
public class User {
    @FieldEncryptor(Md5PoJoFieldEncryptorStrategy.class)
    private String password;
    
    @FieldEncryptor(DefaultPoJoFieldEncryptorPattern.class)
    private String phone;
}
```

```yaml
# 配置文件中覆盖特定字段的加密策略
securt-kit:
  field-encryptor:
    tables:
      test_user:
        fields:
          password:
            strategy: com.chu7.securtkit.encryptor.pojo.AesPoJoFieldEncryptorStrategy
            # 覆盖注解配置，改为AES加密
```

#### 场景2：配置文件为主，注解为辅
```java
// 实体类中只定义字段，不指定加密策略
@TableName("test_user")
public class User {
    private String password;
    private String phone;
    private String email;
}
```

```yaml
# 配置文件中统一管理所有字段的加密策略
securt-kit:
  field-encryptor:
    default-strategy: com.chu7.securtkit.encryptor.pojo.DefaultPoJoFieldEncryptorPattern
    tables:
      test_user:
        fields:
          password:
            strategy: com.chu7.securtkit.encryptor.pojo.Md5PoJoFieldEncryptorStrategy
          phone:
            # 使用默认策略
            enabled: true
          email:
            strategy: com.chu7.securtkit.encryptor.pojo.AesPoJoFieldEncryptorStrategy
```

#### 场景3：环境差异化配置
```yaml
# application-dev.yml (开发环境)
securt-kit:
  field-encryptor:
    default-strategy: com.chu7.securtkit.encryptor.pojo.Base64PoJoFieldEncryptorStrategy
    tables:
      test_user:
        fields:
          password:
            # 开发环境使用简单的Base64编码
            enabled: true

---
# application-prod.yml (生产环境)
securt-kit:
  field-encryptor:
    default-strategy: com.chu7.securtkit.encryptor.pojo.AesPoJoFieldEncryptorStrategy
    tables:
      test_user:
        fields:
          password:
            strategy: com.chu7.securtkit.encryptor.pojo.AesPoJoFieldEncryptorStrategy
            params:
              key: "${ENCRYPTION_KEY:default-key}"
            # 生产环境使用强加密AES
```

## 配置参数说明

### FieldEncryptorProperties 配置

```yaml
securt-kit:
  field-encryptor:
    enabled: true  # 是否启用配置文件字段加密
    default-strategy: "默认策略类全名"  # 可选：默认加密策略，当字段未配置时使用
    tables:        # 表字段配置
      "表名":       # 必填：数据库表名
        enabled: true  # 可选：是否启用该表的字段加密，默认true
        fields:        # 字段配置
          "字段名":     # 必填：数据库字段名
            strategy: "策略类全名"  # 可选：加密策略类全名，为空时使用default-strategy
            params:                # 可选：自定义参数
              key: "custom-key"
              mode: "CBC"
          # 不配置字段名，表示该字段不加密
```

### 支持的加密策略

1. **DefaultPoJoFieldEncryptorPattern** - DES加密
2. **AesPoJoFieldEncryptorStrategy** - AES加密
3. **Base64PoJoFieldEncryptorStrategy** - Base64编码
4. **Md5PoJoFieldEncryptorStrategy** - MD5哈希

## 运行示例


## 最佳实践

### 1. 配置分层
- **基础配置**：在注解中定义默认加密策略
- **环境配置**：在配置文件中覆盖特定环境的策略
- **特殊配置**：在配置文件中处理特殊情况

### 2. 命名规范
- 表名和字段名使用小写
- 策略类名使用完整的包名
- 参数名使用kebab-case

### 3. 安全考虑
- 生产环境的密钥不要硬编码在配置文件中
- 使用环境变量或配置中心管理敏感信息
- 定期轮换加密密钥

### 4. 性能优化
- 避免频繁修改配置文件
- 合理使用缓存机制
- 监控加密解密性能

## 故障排查

### 1. 配置不生效
- 检查 `securt-kit.field-encryptor.enabled` 是否为 `true`
- 检查表名和字段名是否正确（区分大小写）
- 检查策略类名是否正确

### 2. 加密策略找不到
- 检查策略类是否在classpath中
- 检查策略类是否实现了 `FieldEncryptorStrategy` 接口
- 检查策略类是否有无参构造函数

### 3. 配置冲突
- 查看日志中的配置加载顺序
- 确认配置文件中的配置是否正确覆盖了注解配置
- 检查是否有重复的字段配置
